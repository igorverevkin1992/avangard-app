# Решения, принятые при реализации ТЗ Iter Meum v2

Файл ведётся по правилу агента из раздела 14 ТЗ: любая зависимость сверх
списка и любое отступление от буквы ТЗ фиксируются здесь.

| № | Решение | Почему |
| --- | --- | --- |
| D-01 | Sentry удалён вместе со старым слоем. | Раздел 13: «нет аналитики и сторонних SDK, кроме Google Sign-In/Drive». |
| D-02 | У debug-сборки нет `applicationIdSuffix`. | Приложение ставится из APK (раздел 2); OAuth-клиент Google привязан к имени пакета `com.itermeum.app` — суффикс `.debug` сломал бы Sign-In для сборки, которую реально ставит пользователь. |
| D-03 | Зависимость `ui-text-google-fonts` удалена. | Раздел 13: 100 % оффлайн. Шрифты OFL (PT Serif, PT Serif Caption, Cormorant SC, JetBrains Mono) будут вшиты в `res/font` в фазе 9. Проверено: у всех четырёх есть кириллица, включая «Ё». |
| D-04 | Все фазы ведутся коммитами в одной ветке `claude/sleepy-curie-c5lhqh`, по одному коммиту-вехе на фазу. | Правила сессии запрещают пуш в другие ветки без явного разрешения; разбить на отдельные PR можно постфактум. |
| D-05 | Критерий фазы 1 `grep -ri "avangard\|Rand\|Sabotage" src/` трактуется как отсутствие ссылок на старый пакет, Айн Рэнд и Sabotage Protocol. | Регистронезависимый `Rand` ловит `SecureRandom`/`random`, которые нужны для AES-GCM IV (раздел 8, I6) и бэкапа. В коде старых смыслов нет. |
| D-06 | Растровые launcher-иконки не поставляются; только adaptive-icon из векторов (`mipmap-anydpi-v26`). | `minSdk 26` — adaptive icon поддерживается всеми целевыми устройствами. Форма по разделу 12: квадрат со срезанными углами, крест с расширяющимися концами, линия-дорога. |
| D-07 | Добавлены таблицы, которых нет в списке раздела 8: `morning_state` (автомат утреннего блока 5.1, одна строка на день), `jaculatoria_log` (отметки «произнёс» для правила «≥3 в день»), `rosary_progress` (прогресс декад «до 23:59, можно частями»), `monthly_summary_view` («экран просмотрен» для нормы `monthly_summary`). | Правила засчитывания из раздела 4 требуют этих данных; в разделе 8 для них не было сущностей. |
| D-08 | Лекционарий: ссылки с запятой могут начинать новый сегмент с номером главы (`Jn 15:26-27,16:12-15`); парсер `BibleReference` это принимает. Пятидесятница: A — Jn 20:19-23, B и C — годовые альтернативы. | Собственная сборка таблиц (11.2); формат расширен, чтобы не упрощать чтения. Все таблицы помечены `verify:true` до сверки с официальным ordo. |
| D-09 | Тексты молитв: базовая редакция — распространённые русские католические тексты; `verify:true` у всех, кроме крестного знамения, «Слава Отцу», краткого сокрушения и собственных текстов приложения. | Раздел 7.1: пользователь сверяет каждую молитву с тем, как молятся в соборе, и правит в настройках. |
| D-10 | Вознесение и Тело и Кровь Христовы по умолчанию переносятся на воскресенье (E+42, E+63); флаг `LiturgicalCalendar.transferToSunday` — настройка. | В России решением ККЕР эти торжества переносятся на воскресенье; открытый вопрос №4 ТЗ ставил по умолчанию четверг с флагом verify — флаг сохранён как настройка, по умолчанию выбран российский порядок. Подлежит сверке с ordo собора. |
| D-11 | Добавлены зависимости: `androidx.camera:*` 1.3.4 и `com.google.mlkit:barcode-scanning` 17.3.0 (сканирование QR, раздел 5.1 «камера + ML Kit Barcode оффлайн»), `com.google.zxing:core` 3.5.3 (генерация PNG QR-кода для кухни — ML Kit умеет только читать). | Требование ТЗ 5.1/13.5 (QR показать и сохранить PNG). Обе библиотеки работают без сети. |
| D-12 | Три звука будильника (`res/raw/bell_1..3.wav`) синтезированы (затухающие колокольные тона), а не записаны. | Раздел 5.17 требует «3 встроенных звука-колокола»; сторонних аудио-ассетов с ясной лицензией в репозитории нет. |
| D-13 | Экран «Зал» реализован карточкой на вкладке «Сегодня» (таймер «Выход через 10 минут» + кнопки «Зал» / «Домашняя тренировка 20 мин»), а не отдельным `GymCheckScreen`. | После «Serviam» телефон откладывается на 30 минут карантина; отдельный экран, который надо открыть вручную, никто не увидит. Карточка появляется сразу после ответа на вопрос о карантине. |
| D-14 | `norm.pausedUntil` (колонка в схеме v1): механика 6.6 «снизить планку на неделю» ставит неядровую норму на паузу на 7 дней. | Схема v1 ещё не выпущена, миграция не нужна; альтернатива (enabled=false) теряла бы автоматический возврат через неделю. |
| D-15 | Тон уведомлений (5.17): «Спокойно» — всегда формулировки уровня 1 (кроме «под угрозой»), «Твёрдо» — по таблице 6.5, «Сурово» — формулировки уровня 2 уже с первого напоминания по ядровым нормам. Лимиты (8/день, одна «под угрозой», тихие часы, тишина ±90 мин) тон не меняет. | ТЗ задаёт три значения тона, но не их семантику. |
| D-16 | Закрытие дня (оценка стриков) выполняется приёмником точного будильника 03:00 и лениво при открытии «Сегодня» (идемпотентно по `lastCountedDate`); `DayCloseWorker` на WorkManager не добавлялся. | Точный будильник + ленивый проход покрывают сценарий «телефон выключен в 03:00»; второй механизм на WorkManager дублировал бы ту же работу. |
| D-17 | Добавлена зависимость `androidx.glance:glance-appwidget` 1.1.1 для виджета 4×2 (раздел 9). | Единственный поддерживаемый способ писать виджет на Compose-подобном API; работает оффлайн. |
| D-18 | Шрифты вшиты в `res/font`: Cormorant SC (заголовки, капители, +8 % трекинг), PT Serif (текст), JetBrains Mono (таймеры). Лицензии OFL — в `assets/licenses`. Открытый вопрос №8: кириллица в Cormorant SC проверена по cmap (включая «Ё»). | Раздел 12/13: оффлайн и заданная типографика. |
| D-19 | Бэкап: содержимое пакета контента (тексты молитв, стрелы, аскеза, план чтения) в копию не входит — только пользовательские данные и правки пользователя; после восстановления пакет досеивается. | Уменьшает файл и делает копию независимой от версии контент-пакета. |
| D-20 | Заморозки «Милосердие» (6.4): две в месяц на каждый стрик отдельно (верность, подъём, лягушка), ведомость `freeze_ledger` хранит тип стрика. | Иначе пропуск обзвона в понедельник съедал бы заморозки стрика верности; тесты раздела 11.6 исходят из независимого учёта. |
| D-21 | Постоянный ключ подписи (alias `itermeum`, SHA-1 `EE:B5:F0:60:1A:53:98:B1:B5:82:AC:6F:1D:C9:D8:51:30:1D:6D:18`) используется и для debug, и для release. В репозиторий не попадает: CI берёт его из секретов `ITERMEUM_KEYSTORE_B64` и `ITERMEUM_KEYSTORE_PASSWORD`, локальная сборка — из `app/keystore/itermeum.jks` и `keystore.properties`. Без ключа сборка подписывается обычным debug-ключом, вход в Google тогда не работает. | OAuth-клиент Android привязан к паре «пакет + SHA-1»; случайный debug-ключ CI менялся при каждой сборке. Репозиторий публичный, поэтому ключ хранится вне git. |
| D-22 | Время Мессы хранится отдельно для субботы (`massTimeSaturday`, по умолчанию 18:00) и воскресенья (`massTimeSunday`, 10:00); «обычный день» (`massDay`) по-прежнему задаёт напоминание и тихое окно. Схема БД v2 с ручной миграцией 1→2. | Пользователь ходит в разные дни на Мессы с разным временем; одно поле `massTime` заставляло менять время при смене дня. |
| D-23 | Визуальный язык смещён к «католическо-рыцарской» эстетике: тёплый чёрный камень, пергаментный текст, состаренное золото для линеек, крестов-патте и девизов (`tertiary`), двойная рамка панелей, нулевые скругления, геральдические иконки вкладок (кольцо с крестом, меч, чаша, щит), щит с крестом на иконке приложения, золотое кольцо с 12 делениями вокруг круга дня. Литургический цвет остаётся `primary`. | Просьба пользователя после первой установки; раздел 12 ТЗ (плоскость, без градиентов, без скруглений) соблюдён: орнаменты — только линии и векторные фигуры. |
| D-24 | Закрытие дня перенесено на 04:00; после смены часового пояса за последние 24 ч новый день «начинается» с подтверждения подъёма или в 12:00 местного. | Examen «за вчера» принимается до 03:59 (5.12); перелёт не должен закрывать незаконченный день (6.1, 11.6). |
| D-25 | Месса — одна на выходные (суббота/воскресенье): активна в обычный день, если её не было накануне, и в другой день, только если отмечена там. Исповедь активна только по сроку (`confessionEveryDays`). | Еженедельная и ежемесячная нормы не должны ежедневно занижать долю верности. |
| D-26 | Поздний подъём (+20…+60) — SKIP для стрика подъёма; день без активных норм — SKIP; при нулевом стрике промах не тратит «Милосердие». | ТЗ 5.1: «поздний — стрик не растёт, не горит». |
| D-27 | Рабочие нормы сдвигаются вместе с `workStart`; отсечка обзвона — 14:00, но не раньше чем через 2 часа после начала работы. | ТЗ 11.3: рабочие нормы привязаны к `workStart`; при позднем старте «лягушка» иначе недостижима. |
| D-28 | Логический день хранит корень приложения: при его смене граф навигации и все ViewModel пересоздаются. | Единый механизм вместо тикеров в каждом экране. |
| D-29 | Лимит L3 в день тратит только «стрик под угрозой»; напоминание 13:40 о звонках говорит текстом уровня 3, но учитывается как L2. Карантин и проверка будильника входят в лимит 8/день. | ТЗ 6.5. |
| D-30 | Только arm64-v8a в APK; колокола в OGG; шрифты подмножеством (латиница, кириллица, знаки). Схемы Room лежат в `app/schemas` и попадают только в debug-ассеты (для тестов миграций). | Приложение ставится на один известный телефон; размер APK. |
| D-31 | Robolectric получает `android-all` через Gradle в офлайн-режиме. | Maven Central отвечал 429 при загрузке самим Robolectric. |
| D-32 | Examen под PIN — системный экран подтверждения устройства (`createConfirmDeviceCredentialIntent`), без отдельной библиотеки биометрии. Светлая тема — локальная настройка устройства, не входит в бэкап. | Меньше зависимостей; то же поведение (PIN/отпечаток телефона). |
| D-33 | Упрощённый интерфейс. «Сегодня» отвечает на «что делать сейчас?»: строка статуса (дата, праздник, малое кольцо «N из M», дни верности), одна карточка «Сейчас» с одним действием (утренний поток, пятничный выбор, следующая норма), остальное — свёрнутыми группами Утро / День / Вечер; «Болею», «Болею завтра», «Снизить планку» и настройки — в меню «⋯». Три стрика, звонки и задачи ушли с «Сегодня» в «Путь» и «Труд»; карточка сценария — в «Труд». «Труд» идёт по ходу дня (план → звонки → последний камень), ритуал/проекты/студия свёрнуты в «Ещё». «Молитва» — «Сегодня» + свёрнутая «Библиотека». Настройки — семь свёрнутых разделов. | Пользователь: интерфейс перегружен, не разобраться. Раздел 9 ТЗ описывал больше блоков на «Сегодня»; логика, нормы и стрики не менялись. |
| D-34 | Рабочий день без открытия приложения. (1) В рабочие часы будней в шторке и на экране блокировки висит одна «рабочая карточка» с текущим шагом (план → герои до отсечки → задачи → последний камень) и кнопками «+1 герой», «Договорился», «Задача ✓»; при смене шага — одна короткая вибрация, без звука; в лимит 8/день не входит (это статус, а не напоминание). Напоминания уровня 1 о плане, героях и последнем камне заменены карточкой; уровни 2–3 и «под угрозой» сохранены. (2) План дня составляется заранее: шаг «План на завтра» в Examen и карточка «План дня — до работы» утром; план, сохранённый накануне, засчитывается за свой день. (3) В рабочие часы прочие напоминания приходят в тихий канал (без звука и всплывания). (4) Вечерний «Что было сегодня» в начале Examen рабочего дня: недостающие попытки и задачи записываются после отсечки — в статистику и подсказки разбора, не в стрики. Автоподсчёт по журналу звонков не делается: операционные звонки неотличимы от звонков героям. Стрик «Лягушка» в интерфейсе назван «Герои». | Пользователь: в загруженный день нет времени открывать приложение, работа идёт хаотично; звонков много, и большая часть — операционка. |
| D-35 | Норма «Лягушка» (обзвон героев до 14:00) выключена по умолчанию и выведена из ядра; при обновлении она выключается у существующей установки. Ядро — подъём и Examen. Стрик «Герои» пропускается, пока норма выключена, и показывается в «Пути» только если когда-либо был. Звонки героям остаются задачей 1 плана дня; журнал попыток и кнопки «+1 герой» / «Договорился» на рабочей карточке появляются на задаче типа «поиск героев». Норму можно вернуть в Настройках → «Нормы». | «Съешь лягушку» — приём тайм-менеджмента Брайана Трейси, не практика Opus Dei; пользователь попросил её убрать. |
| D-36 | На рабочей карточке звонок героям отмечается исходом: «Договорился», «Вернуться», «Отказ» (вместо «+1 герой»). Каждая кнопка — одна попытка в журнале обзвона; новый исход `CALLBACK` («вернуться») добавлен и на экран «Обзвон». В тексте карточки — счёт «договорились · вернуться · отказ». Android показывает не больше трёх кнопок, поэтому задача «поиск героев» закрывается в «Труде» по нажатию на карточку; когда попыток набрано на цель, карточка об этом говорит. | Просьба пользователя: из шторки нужен исход разговора, а не просто счётчик. |
| D-37 | Книги для духовного чтения загружаются в приложение файлом с телефона (EPUB, FB2 и FB2.ZIP, TXT в UTF-8 или windows-1251, PDF) и читаются внутри: оглавление, размер шрифта, место остановки, таймер чтения запускается при открытии книги. EPUB/FB2/TXT разбираются в главы и абзацы собственным парсером без зависимостей; PDF показывается страницами через системный `PdfRenderer`. Файлы лежат только в личной папке приложения: в репозитории и контент-пакете текстов книг нет, в резервную копию они не входят. | Права на тексты св. Хосемарии (Fundación Studium), книги Хаварда и издания — у правообладателей, репозиторий публичный. Пользователь загружает свои экземпляры. |
| D-38 | Справочник «Практики» (меню ⋯ на «Сегодня»): что это за практика, откуда она (Opus Dei / общекатолическая / дисциплина приложения) и как приложение её отмечает. Текст — `assets/content/practices.json`. | Просьба пользователя: описание норм всегда под рукой. |
| D-39 | Результат входа в Google показывается всегда: «Вход выполнен: адрес» или причина по коду (10 — Android-клиент OAuth не совпадает с пакетом и SHA-1; 12500 — нет в тест-пользователях или не включён Drive API; 12501 — отменено; 7 — нет сети). | Вход «молча» не срабатывал, и причину было не узнать. |
