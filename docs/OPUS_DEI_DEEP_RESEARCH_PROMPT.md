# Промпт для глубокого исследования: ТЗ на переработку Prime Mover → Opus Dei

> Скопируйте всё, что ниже горизонтальной черты, в инструмент глубокого исследования
> (Deep Research). Приложите к запросу PDF «Богословие труда, институциональная система
> и управленческая практика Opus Dei в работе телевизионного и кинопродюсера».

---

## РОЛЬ

Ты — ведущий продуктовый аналитик и Android-архитектор, одновременно хорошо
разбирающийся в католической духовности и конкретно в духовности Opus Dei
(св. Хосемария Эскрива). Твоя задача — провести исчерпывающее исследование и на его
основе написать **техническое задание (ТЗ) для Claude Code** на полную переработку
существующего Android-приложения **Prime Mover** в приложение, помогающее одному
человеку ежедневно жить по духовности Opus Dei: «План жизни» (Plan de Vida),
освящение труда, молитвы, практики, формация и этика профессионала.

ТЗ будет исполнять ИИ-агент (Claude Code), работающий непосредственно в репозитории.
Поэтому ТЗ должно быть **однозначным, модульным, проверяемым** и написано так, чтобы
агент мог реализовать его без уточняющих вопросов. Язык ТЗ — русский; идентификаторы
кода — английские.

## КОНТЕКСТ 1. Кто пользователь

- Один пользователь, живёт и работает в Москве. Профессионал в медиапроизводстве
  (продюсирование, генеративный ИИ-контент, сериалы/шоу). Ненормированный график:
  офисные дни, длинные съёмочные смены, командировки.
- По приложенному исследованию — человек, пришедший к вере во взрослом возрасте,
  проходящий (или готовый проходить) катехизацию; **не член прелатуры**. Это важно:
  приложение должно корректно разделять практики, доступные любому мирянину /
  катехумену (ментальная молитва, Розарий, Examen, духовное причастие, чтение), и
  обязательства, которые принимают только инкорпорированные члены (например,
  Preces, круги, обязательная еженедельная исповедь как норма). Приложение не должно
  изображать членство или имитировать официальные материалы прелатуры.
- Пользователь — одиночный «оператор»; команды нет, сверху никто не контролирует.
  Приложение должно быть для него внешней дисциплинирующей структурой.
- Философия текущего приложения: никакой геймификации, никаких конфетти, никаких
  стриков с «огоньком». Эту установку нужно сохранить, но переосмыслить в
  католическом ключе (единственная награда — спокойное *Deo omnis gloria*).

## КОНТЕКСТ 2. Что уже есть — текущее приложение Prime Mover

Репозиторий: `igorverevkin1992/avangard-app`, пакет `com.avangard.app`, версия 0.1.0.
Это нативное Android-приложение, 161 Kotlin-файл, 31 файл тестов.

**Стек (сохранить):** Kotlin 2.0.21, `minSdk 26`, `targetSdk 34`, `compileSdk 35`,
Jetpack Compose (BOM 2024.12) + Material3, Hilt 2.52 (+ HiltWorker), Room 2.6.1 (KSP,
БД версии 9, миграции 1→9 покрыты тестами), Navigation Compose 2.8.5, DataStore
Preferences, kotlinx.serialization, WorkManager + OkHttp (Google Drive AppData sync),
AlarmManager (планировщики), Foreground Service + Quick Settings tile. Тесты:
Robolectric + JUnit4 + mockk + Turbine. CI: GitHub Actions (`build.yml`).

**Архитектура (Clean-ish):** `core/domain` (model, repository-интерфейсы, use-case'ы) →
`core/data` (Room-репозитории, DataStore, cloud) → `feature/*` (Compose-экраны + VM) →
`sync/*` (notifications, scheduler, service, tile). Тема — `MachineTheme` на палитре
ISA-101 («индустриальный пульт»), монохром + зелёный `Approve`.

**Текущие функции (каждую нужно будет явно отнести к одному из решений:
оставить / трансформировать / удалить):**

1. **Пять направлений дня**: 01 ГЕНЕРАЦИИ (Ядро), 02 ИСПАНСКИЙ, 03 СПОРТ,
   04 НАСМОТРЕННОСТЬ, 05 ЧТЕНИЕ (инфраструктура). Каждое — карточка на главном
   экране «ПУЛЬТ» со статусом Done/NotDone.
2. **Режим дня** СТАНДАРТ / МИНИМУМ (MVD): один тумблер, фиксируется на сутки
   после первого выбора, критерии «что считается стандартом/минимумом» для каждой
   привычки задаются пользователем во вкладке РЕЖИМ → КРИТЕРИИ.
3. **Flash-сессии («ВСПЫШКА»)**: таймер фокуса по направлению, `HH:MM:SS`, после
   5 минут цвет меняется на зелёный; персистируется в `focus_session`; одна активная
   сессия гарантируется partial unique index в SQLite; sticky foreground-уведомление;
   QS-тайл; опциональный Pomodoro-автостоп.
4. **Авторизация и «АНАЛИЗ ГЕНЕРАЦИИ»**: после сессии по Ядру — модалка с вопросом
   «Присутствует ли в этом результате мой инженерный расчёт?», обязательный текст +
   чекбокс. Только это определяет классификацию дня.
5. **Earned Pride**: 2,5 секунды заблокированного UI с мантрой
   «ФАКТ УСТАНОВЛЕН. РЕСУРС КОНВЕРТИРОВАН В КАПИТАЛ. A = A».
6. **Soft Core primacy**: баннер-напоминание, бейдж «ГЛАВНОЕ ДЕЛО», полуденный push
   в 12:00.
7. **Sabotage Protocol**: три CBT-скрипта (ИМПУЛЬС ПОДМЕНЫ / РЕАКЦИЯ НА БРАК /
   СОЦИАЛЬНОЕ СРАВНЕНИЕ), каждое открытие логируется в `evasion_log`.
8. **Evening Close** (21:00 push): три авто-индикатора
   (ПРОДУКТИВНОСТЬ/ГОРДОСТЬ/ЦЕЛОСТНОСТЬ), четыре virtue-селектора `[−][0][+]`
   (Разумность / Независимость / Честность / Справедливость — объективистские
   добродетели), условный dropdown Defect/Waste, свободный журнал, follow-up
   прошлого bottleneck. Идемпотентно.
9. **Sunday PDCA Audit**: история заблокирована в будни (`WeekdayLockScreen`), в
   воскресенье стартовый экран — аудит недели: метрики, дельты, выбор одного
   bottleneck из фиксированного списка, затем доступ к месячной сетке привычек.
10. **Хронометр**: LifeGrid — мозаика недель жизни, окрашенных по статусу
    (Извлечена / Частично / Упущена) на основе режима дня; утренний push
    «ИГНИЦИЯ» со статусом вчерашнего дня.
11. **Библиотека**: цитаты из объективистского whitepaper'а, индексированы по
    четырём virtue-тегам, «цитата дня» детерминирована по epoch-day, пин цитат.
12. **Cloud sync**: Google Sign-In, бэкап в Drive `appDataFolder`, `SyncCoordinator`
    с дебаунсом, `SyncUploadWorker`, восстановление при первом входе, ручной
    бэкап/восстановление/wipe в настройках.
13. **Навигация**: bottom-nav из 5 вкладок ПУЛЬТ / БИБЛИОТЕКА / ОЦЕНКА / ТРЕКЕР /
    РЕЖИМ; модальные экраны скрывают нав-бар.
14. **Схема данных**: `daily_session` (одна строка на день: core_mode, статус Ядра +
    prompt + authorised_at, статусы 02–05, вечернее закрытие + virtues, bottleneck,
    journal), `habit_log` (date, habit_code), `focus_session` (лог сессий). Настройки
    и побочные структуры — в DataStore.

Идеологическая основа текущей версии — объективизм (Айн Рэнд, `A = A`, «ресурс →
капитал»). Её нужно **полностью заменить** на католическую антропологию и духовность
Opus Dei, сохранив инженерную строгость, монохромность и отказ от геймификации.

## КОНТЕКСТ 3. Что уже исследовано (приложенный PDF) — НЕ исследовать заново, а использовать

## ПРАВИЛА КАЧЕСТВА

- Пиши для исполнителя-агента: конкретика, а не рассуждения. Каждое требование —
  проверяемое. Избегай «по возможности», «желательно».
- Различай факт / рекомендацию / гипотезу; ставь уровень уверенности там, где

- Богословская корректность важнее «фич»: ничего, что противоречит католическому
  учению или искажает практики Opus Dei; при сомнении — консервативный вариант и
  ссылка на официальный источник (opusdei.org/ru, escriva.org/ru, vatican.va).
- Уважение к пользователю-не-члену: приложение — личный инструмент, не имитация
  формации прелатуры; явно поощряй живой контакт с центром и священником, а не замену
  его приложением.
- Сохраняй инженерную эстетику Prime Mover (строгость, тишина, отсутствие наград),
  но замени его антропологию.
- Не копируй большие фрагменты защищённых текстов; цитаты — короткие, с атрибуцией.
- Формат: Markdown, таблицы там, где сравнение; кодовые идентификаторы в
  `backticks`; язык — русский.
