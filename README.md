# Iter Meum

Личное Android-приложение одного человека: труд, молитва, путь к купели — по
нормам благочестия Opus Dei и этике освящённого труда. Интерфейс на русском,
делалось для Xiaomi 13T Pro (HyperOS), работает на Android 8+.

Основа — документ «ТЗ Iter Meum v2» (фазы 1–9). Всё, что решено по ходу
(D-01…D-71), с причинами, — в [`docs/DECISIONS.md`](docs/DECISIONS.md).
Описание каждой практики для пользователя — в самом приложении: ⋯ → «Практики»
(`assets/content/practices.json`).

## Установка

Каждая сборка ветки `claude/sleepy-curie-c5lhqh` выкладывается в релиз
[`latest`](https://github.com/igorverevkin1992/avangard-app/releases/tag/latest)
(файл `itermeum.apk`, без входа в GitHub). Ставить поверх установленного
приложения: база, настройки и загруженные книги сохраняются, схема БД
обновляется миграциями.

## Что внутри

### Сегодня
Отвечает на вопрос «что делать сейчас?» (D-33).
- **Строка статуса** — дата, праздник в литургическом цвете, кольцо дня, дни верности;
  если приняты зароки — «Зароки: Трезвость 23 · Чистота 5».
- **Карточка «Сейчас»** — одно действие: утренний поток, выбор пятничного
  умерщвления, план до работы, следующая норма.
- **Остальной день** — свёрнут на «Утро / День / Вечер».
- **Утро** — будильник, подтверждение подъёма (QR на кухне; без QR — шаги из трёх
  источников, D-46, или код наоборот), SERVIAM, «30 минут без мессенджеров»,
  утренняя молитва, зал. На время проверки есть «Выключить без подтверждения» (D-47).
- **Меню ⋯** — «Практики», «Зароки», настройки, «Болею сегодня / завтра», «Снизить планку».
- **Стрик «под угрозой»** различает «не хватает норм» и «нужен Examen» (D-45).

### Труд
- Молитва перед началом доброго дела, «Поработал над сценарием» до 12:00.
- **План дня**: три слота и больше (до 10), порядок ↑↓, «Сделать следующей».
  Сохраняется без звонков героям и засчитывается, если сделан до workStart + 30
  (можно накануне в Examen).
- **Задачи** (D-64): быстрый ввод одной строкой со сроком (сегодня / завтра / на
  неделе / без срока), «Входящие и сроки», поиск. Задачи на сегодня сами встают в
  план, «Перенести» отправляет задачу на завтра, убранная из плана возвращается
  во входящие.
- **Карточка задачи**: шаги, заметки со списками, контакт с «Позвонить», ссылка,
  проект, затраченное время. У каждого слота плана есть своя карточка.
- **Фокус** на задаче — таймер в шторке («Пауза» / «Готово»).
- **Обзвон героев** в любое время дня, исход «Договорился / Вернуться / Отказ»
  (D-36, D-60). Норма «Обзвон героев» выключена по умолчанию (D-35).
- **Последний камень**: чеклист из 4 пунктов по типу задачи, «закрыто с долгом»,
  итог дня (закрыто / перенесено / фокус).
- В разделе «Ещё»: ритуал перехода со случайной стрелой Opus Dei (D-52),
  проекты с этическим фильтром и своими задачами, студия.

### Молитва
- **Порядок дня**: утренняя молитва, ментальная молитва (таймер), Евангелие дня
  (Синодальный перевод + собственный лекционарий A/B/C, I/II), Ангел Господень /
  Царица Небесная, стрелы по ситуациям (в том числе «Искушение»), Розарий,
  Месса в выбранный день (D-70), «Радуйся, Царица» по субботам, Examen.
  Молитва перед сном — в конце Examen.
- **Розарий** — по бусинам. Вступление с Никейским Символом веры (D-66, D-71),
  тайны по дням, шаг назад, место сохраняется. В Великий пост — «Крестный путь»,
  в октябре — «Святой Розарий».
- **Examen**: «что было сегодня», присутствие, благодарность, пять вопросов с
  подсказками по данным дня, шаг зарока, сокрушение, propósito с валидатором,
  план на завтра, три «Радуйся, Мария». Можно закрыть PIN-кодом телефона.
- **Духовное чтение** — книги загружаются файлом с телефона (D-37): EPUB, FB2,
  FB2.ZIP, TXT, PDF. PDF с текстом разбирается в главы (PdfBox, D-40), скан
  остаётся страницами.
  - Читалка: размер шрифта, место остановки с точностью до абзаца, «Продолжить
    чтение», таймер чтения продолжает день (D-59).
  - У Библии оглавление по книгам: Завет → книга → сетка глав, сверху «Бытие 3» (D-68).
  - Каждый день показаны Библия, Катехизис и «Беседы»; остальное — в «Все книги
    программы».
- **Библиотека**: повторение молитв (SM-2 с ежедневным повтором на этапе
  заучивания, D-55), молитвенник с правкой текста, литургический календарь,
  круговая диаграмма литургического года (D-54).
- **Тексты молитв** — в редакциях прихода (D-56, D-71).

### Путь
- Стрики верности и подъёма (стрик «Герои» — если норма включена), заморозки
  «Милосердие», вехи — тихие экраны с латынью и стихом.
- Счётчик зарока.
- Катехизация с заметкой (тезисы списком), обзор недели (в том числе «Труд за
  неделю»), итог месяца, квартальная проверка, «Я крещён», Летопись.

### Зароки (D-67, D-79)
- Три постоянных приношения без срока, каждое принимается отдельно: **трезвость**
  (алкоголь), **чистота** (мастурбация), **без компьютерных игр**. Не нормы дня.
- Намерение и кому позвонить; у трезвости ещё ответ на застолье и напоминание за час.
- День подтверждается в Examen (по вопросу на зарок) или утром за вчера; можно
  ответить до недели назад. Засчитываются только отвеченные дни. «Нет» обнуляет
  только свою серию (лучшая серия и все дни остаются), на экране «Nunc coepi».
  На стрики верности и подъёма зароки не влияют.
- **Трудная минута** — своя у каждого: намерение, 10 минут переждать (отсчёт в
  шторке), стрелы; у трезвости — молитва св. апостолу Матфию, у чистоты — три
  «Радуйся, Мария»; звонок.
- Вехи 7 / 30 / 40 / 100 / 365 дней — у каждого свои.
- На экране блокировки о зароках ничего не видно.

### Шторка
- **Рабочая карточка** (D-34) в рабочие часы: текущий шаг дня (план → герои →
  задачи → последний камень), кнопки исхода звонка, «Задача ✓», «+ задача»
  (ответ прямо из шторки).
- **Карточка таймера**: молитва, чтение, фокус, «переждать».
- Карточки выкладываются один раз и обновляются только по делу: каждое обновление
  включает экран блокировки HyperOS (D-65).
- Плитка быстрых настроек и виджет 4×2.

### Система
- Логический день 03:00–02:59, закрытие дня в 04:00.
- 26 норм, расписание с тихими окнами вокруг Мессы и катехизации.
- Эскалация уведомлений с лимитом 8 в день.
- Точные будильники и HyperOS-чеклист.
- Шифрование полей через Keystore; бэкап v1 (AES-256-GCM, PBKDF2 210 000) в
  Google Drive AppData. Загруженные книги в бэкап не входят — после восстановления
  их нужно загрузить заново.
- Поля ввода начинают предложения с заглавной; в заметках есть списки «•» и «1.» (D-69).

## Сборка

Ключ подписи в репозиторий не кладётся:
- локально — файл `app/keystore/itermeum.jks` и в корне репозитория
  `keystore.properties` со строкой `storePassword=…`;
- в CI — секреты `ITERMEUM_KEYSTORE_B64` и `ITERMEUM_KEYSTORE_PASSWORD`.

```
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Нужны JDK 17, Android SDK 35 (`platforms;android-35`, `build-tools;35.0.0`) и
`local.properties` с `sdk.dir`. Стек: Kotlin 2.0, Jetpack Compose (Material 3),
Hilt, Room (KSP), kotlinx.serialization, Glance, CameraX + ML Kit (QR),
PdfBox-Android.

**CI** (`.github/workflows/build.yml`), на каждый push:
1. Юнит-тесты (Robolectric, миграции по настоящим схемам).
2. Проверка, что схема Room закоммичена.
3. Debug- и release-сборка (R8).
4. Lint.
5. Отпечаток ключа подписи.
6. Артефакты `itermeum-debug-apk`, `itermeum-release` (APK + mapping),
   `lint-report`, `unit-test-results`.
7. Для этой ветки — публикация APK в релиз `latest`, с повтором при сбое API GitHub.

**Изменение схемы БД** (сейчас версия 4):
1. Поднять версию в `AppDatabase`.
2. Написать миграцию в `Migrations.kt` и тест в `MigrationsTest`.
3. Закоммитить новый `app/schemas/com.itermeum.app.core.database.AppDatabase/N.json`.

Без Android SDK файл схемы берётся из лога CI: шаг «Room schema is committed»
печатает новый файл в base64 между `=== SCHEMA … ===` и `=== END ===`.

**Изменение контента** (`app/src/main/assets/content/*.json`): поднять
`contentPackVersion` в `prayers.json` (сейчас 10). Тогда при запуске обновятся
тексты молитв, стрелы, план чтения и вехи; правки молитв, сделанные пользователем,
сохраняются.

## Что нужно сделать вручную

- **Google Sign-In** требует OAuth-клиента Android в Google Cloud для пакета
  `com.itermeum.app` с SHA-1 ключа подписи
  `EE:B5:F0:60:1A:53:98:B1:B5:82:AC:6F:1D:C9:D8:51:30:1D:6D:18` (D-21). Включённого
  Drive API и тестового пользователя. Результат входа и причина ошибки видны в
  настройках (D-39). Без входа бэкап в Drive выключен, локально всё работает.
- **Тексты книг** (Путь, Беседы, Кузня, Катехизис, Библия и др.) в репозитории
  не хранятся: права у издателей, файлы загружает пользователь.
- **Сверка текстов**: 7 молитв и 12 стрел ещё помечены `verify: true`. Их нужно
  сверить с официальными изданиями и снять пометку. Тексты, присланные
  пользователем, уже подтверждены.

## Устройство кода

- `core/` — данные:
  - `database` — Room, миграции;
  - `data` — репозитории, в том числе `books` (разбор книг) и таймеры;
  - `engine` — чистая логика: расписание, стрики, SM-2, Examen, зарок;
  - `liturgy` — календарь и лекционарий;
  - `content` — контент-пакет;
  - `backup`, `designsystem`.
- `feature/` — экраны: `today`, `work`, `prayer`, `path`, `examen`, `vow`,
  `settings`, `onboarding`, `about`, `morning`.
- `sync/` — будильники, уведомления, рабочая карточка, сервис таймера, напоминания
  зарока, виджет, плитка.
- `docs/DECISIONS.md` — журнал решений.
